## 1. 结论与部署状态

## 3. 为什么保留私有存储

CloudBase 的 PRIVATE 基础权限是“仅创建者及管理员可读写”。安全规则里的 `resource.openid` 表示文件创建者标识，不是路径中的一段字符串。管理员或服务端可以在完成业务权限判断后签发文件访问链接。[基础权限](https://docs.cloudbase.net/storage/data-permission)、[管理端存储 API](https://docs.cloudbase.net/api-reference/manager/node/storage)、[安全规则](https://docs.cloudbase.net/storage/security-rules)、[SDK 文件访问](https://docs.cloudbase.net/storage/sdk)

当前选择的边界：

1. **上传阶段**：用户主动选择 1–3 张照片，确认公开意愿；原图只进入本人的 pending 路径。私人健康档案、原有目击和小屋照片不自动加入投稿。
2. **待审阶段**：服务端检查当前环境、路径、格式、大小和原图 SHA-256；投稿保持 pending。公共列表不能取得待审原图。
3. **人工审核阶段**：运营人员在本地查看完整文字、猫咪名片和每一张实际照片，决定批准或拒绝。不能只看缩略图或文件名。
4. **批准阶段**：云端再次验证源图哈希，转码并去除 EXIF/GPS 等元数据；每次尝试使用新的 256 位随机路径创建展示副本，回读大小和哈希。全部成功后才更新审核状态。
5. **展示阶段**：公共查询只投影已审核记录中的展示副本，由服务端签发访问链接。客户端不直接把任意文件 ID 兑换成公共照片。

仅禁止普通用户覆盖、删除**已经存在的服务端展示副本**，结合不可预测路径、回读校验和私有数据库白名单，就能建立第一版的文件完整性边界。普通用户即使在相似目录新建无关文件，也不会自动进入首页；目录名本身不等于审核结果。

临时链接是持有即能访问的短期凭据，不应记录到日志、长期保存或转发。客户端的链接刷新时间不应夸大为已经验证的提供方撤销时限。用户已经看到或下载的公开照片，也无法靠链接过期收回。

不将整桶权限调整为公共读取；不为上线改动旧档案、小屋和其他云函数。存储滥用配额、闲置上传回收、举报与已公开内容撤下，仍需持续完善。

## 4. 运营人员如何审核

工具为仓库内 `tools/community_review.py`。它只使用既有 CloudBase CLI 登录态，限定当前环境、`catCommunity` 和 `cc_posts_private`；不会自动批准用户投稿。

前提：本机 Python、Node.js、CloudBase CLI 可用，CLI 已登录且有本环境的管理权限。不要把审核密钥写进命令行或小程序。工具会在审核时重新读取云端函数配置，将密钥只保留在内存中。

以下命令均在仓库根目录运行。`post_…`、`64位请求哈希`、报告路径需要替换成命令返回的真实值。

### 4.1 查看待审列表（只读）

```powershell
python tools/community_review.py --env-id cloud1-d6gpjpxunc74669d7 list --limit 20
```

输出投稿编号、完整正文、白名单猫咪名片、昵称、图片数量和请求哈希；不输出原始微信身份、密钥、签名或临时图片 URL。单页最多 50 条；若返回 `nextAfter`，可继续：

```powershell
python tools/community_review.py --env-id cloud1-d6gpjpxunc74669d7 list --limit 20 --after "post_上一页最后编号"
```

### 4.2 准备本地审核报告（只读云端）

```powershell
python tools/community_review.py --env-id cloud1-d6gpjpxunc74669d7 prepare --post "post_待审编号"
```

工具下载当前投稿的确切 pending 图片：限定当前环境和存储桶，HTTPS，不跟随跳转；有界读取最多 5MB 加一个超限判定字节，并设置下载时限。每张图片须与提交时记录的大小、格式及 SHA-256 相符。

输出中的 `report` 是本地 HTML，`manifest` 是配套 JSON。文件保存于已被 Git 忽略的 `artifacts/community-review/` 子目录；HTML 包含完整文字、猫咪名片和所有照片，没有自动发布按钮。

运营人员应打开 `report` 并逐项检查：

- 照片和文字是否适合公开，是否确实属于这次猫咪故事。
- 是否出现可识别人脸、门牌、家庭住址、联系方式、二维码等需要处理的信息。
- 是否存在不适宜内容、诱导信息或明显侵犯他人权益的素材。
- 是否逐张检查了全部照片，而不是只检查封面。

不确定时不要批准。报告是私人投稿的本地副本，可能仍含原图元数据；不要分享报告、上传到 GitHub 或放入公共网页。审核完成后按自己的保留制度清理本地副本。

### 4.3 明确批准

确认已检查文字与全部照片后，复制 `prepare` 输出中的 `requestHash`、`manifest` 路径：

```powershell
python tools/community_review.py --env-id cloud1-d6gpjpxunc74669d7 approve --apply --post "post_待审编号" --request-hash "64位请求哈希" --report-manifest "D:\实际报告目录\manifest.json" --reason "已人工检查全文及全部照片，允许公开" --reviewed-text --reviewed-images
```

批准必须同时具有 `--apply`、准备报告、`--reviewed-text`、`--reviewed-images`。这些旗标是运营人员的明确确认，不代表工具自动完成了内容审核。

工具批准前会重新读取投稿，检查报告、本地图片和云端当前源图的哈希及资料是否一致；随后生成短期 HMAC 请求，以临时文件传给云函数。签名不出现在命令参数或结果中，临时请求文件在结束时清理。只有云端确认且数据库状态与本次审核编号回读一致，才报告成功。

如果配置仍关闭照片共享，批准照片会失败，不会擅自打开开关。如果图片或正文变化，需重新 `prepare` 并重新人工检查。若调用结果不确定，先查看当前投稿状态，不能把重试当成必然失败或成功。

### 4.4 明确拒绝

```powershell
python tools/community_review.py --env-id cloud1-d6gpjpxunc74669d7 reject --apply --post "post_待审编号" --request-hash "64位请求哈希" --reason "照片含可识别的家庭门牌，请处理后重新投稿"
```

拒绝不要求图片批准确认旗标；同样验证准确投稿编号、当前请求哈希和待审状态。拒绝不会把照片公开。当前 CLI 针对待审记录，不是已公开内容的撤下工具。

## 5. 验证与尚未覆盖的边界

审核 CLI 子集新增 49 项离线测试；连同部署、诊断和启用门禁工具共 242 项通过。测试覆盖作用范围、下载大小与时限、源图哈希、HTML 转义、报告篡改、缺少 `--apply` 或人工确认、签名过期、临时文件清理、敏感输出保护及审核后回读。离线测试不读取真实投稿，也不代替文首另行记录的云端验证。

真实验证边界：

- 已验证当前账号上传、待审本人可见、公共列表不含待审记录。
- 已用联调夹具走通签名审核，服务端生成 JPEG 副本，而非直接公开 PNG 原图；Sharp 去元数据另有实际字节单元测试。
- 已验证真实客户端无法覆盖、删除本轮服务端探针对象，回读哈希不变。
- 保留 PRIVATE 基础权限，原图和私有旧资料未获得整桶匿名读取权限；本轮无签名访问探针被拒。
- 待验证第二个真实微信账号的公开查看、待审隔离、回复和通知。

目前第二个真实微信账号尚未验收，不能以合成 A/B 单元测试代替。云端函数部署也不代表小程序已提交微信审核、已经发布，或当前主体已满足公开社区的服务类目、隐私和运营条件。

微信自动图片审核是后续独立增量。未核实现行接口和可信回调来源前，不直接用历史 `imgSecCheck` 示例代替当前审核；更不能只因请求包含 `wxa_media_check` 字段就批准。异步方案需要可信验签、应用身份与任务绑定、源图哈希绑定、幂等及超时保持待审等完整处理。
