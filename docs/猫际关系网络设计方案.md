# Cat-AI 猫际关系网络设计方案

## 1. 产品目标

“猫际关系网络”不是让模型给猫咪贴性格或亲疏标签，而是帮助多猫家庭持续记录可观察行为：哪些猫经常靠近、玩耍或平静共处，哪些组合需要更多空间与资源。首版以用户确认的信息为准，AI 仅在后续阶段协助整理文字记录。

核心价值：

- 区分家庭中的不同猫咪，并从单猫档案进入多猫关系视角。
- 将零散观察变成可回顾的关系卡，辅助安排食盆、猫砂盆、休息区和引入流程。
- 对持续追逐、堵路、护食、躲藏或突然行为改变给出克制的安全提示。

## 2. GitHub 调研与技术取舍

本次使用 GitHub CLI 以 `relationship graph`、`social network graph`、`family tree`、`knowledge graph`、`pet social network`、`WeChat miniprogram graph`、`Canvas graph` 等组合词检索仓库名称与描述，并对活跃度、许可证、运行平台和依赖体量进行二次筛选。GitHub 项目持续变化，因此这里保存的是与本项目技术路径有关的代表性结果，而不是把所有命中仓库直接列为依赖。

| 项目 | 可参考部分 | 对 Cat-AI 的结论 |
|---|---|---|
| [ecomfe/echarts-for-weixin](https://github.com/ecomfe/echarts-for-weixin) | 微信小程序 Canvas 适配和 ECharts 图表组件 | 技术上可行，但完整图表库会增加包体；关系节点少时不值得首版引入 |
| [antvis/G6](https://github.com/antvis/G6) | 图布局、节点拖拽、聚类与交互模型 | 适合未来 Web 管理端或关系规模明显扩大后使用，不直接塞入当前原生小程序 |
| [relation-graph/relation-graph](https://github.com/relation-graph/relation-graph) | 关系图编辑、节点/边定制、焦点视图 | 采用其“焦点节点 + 邻接关系”的信息组织方式，放弃框架依赖 |
| [cytoscape/cytoscape.js](https://github.com/cytoscape/cytoscape.js) | 图分析、最短路径、中心性与多种布局 | 作为后续复杂分析参考；当前猫咪数量小，不需要图分析引擎 |
| [d3/d3-force](https://github.com/d3/d3-force) | 力导向布局算法 | 自由布局视觉活泼，但位置漂移会降低宠物档案的可读性和可预测性 |
| [antvis/F6](https://github.com/antvis/F6) | 面向移动端的图渲染与布局 | 比 G6 更接近移动场景，但仓库示例主要面向支付宝小程序，当前微信原生项目不直接依赖 |
| [vasturiano/react-force-graph](https://github.com/vasturiano/react-force-graph) | 2D、3D、VR/AR 力导图和邻居高亮 | 适合参考聚焦动画，依赖 React/WebGL，不适配当前 WXML 页面 |
| [jacomyal/sigma.js](https://github.com/jacomyal/sigma.js) | 数千节点网络的 WebGL 渲染 | 面向大规模网络，明显超出家庭猫数量与小程序包体需求 |
| [neo4j/neo4j](https://github.com/neo4j/neo4j) | 属性图数据模型和关系查询 | 多家庭、公开社交或大规模推荐阶段才有价值；当前本地档案无需独立图数据库 |
| [networkx/networkx](https://github.com/networkx/networkx) | 路径、中心性、社区发现等服务端图算法 | 未来研究猫群或生成推荐时再考虑；首版不需要 Python 图分析 |
| [ErikGartner/dTree](https://github.com/ErikGartner/dTree) | 多父母家谱树布局 | 可用于独立“猫咪家族树”，不应与日常互动网混成一张图 |
| [donatso/family-chart](https://github.com/donatso/family-chart) | 基于 D3 的家谱编辑与可视化 | 参考亲缘资料的层级呈现；不能凭外貌自动生成亲缘边 |
| [liuhuanyong/PersonRelationKnowledgeGraph](https://github.com/liuhuanyong/PersonRelationKnowledgeGraph) | 实体、关系抽取、知识问答的分层 | 只参考“实体—关系—证据”建模；人物 NLP 模型与源码不用于猫咪关系 |
| [hmorange/-yoiyoi-miniprogram](https://github.com/hmorange/-yoiyoi-miniprogram) | 宠物陪伴小程序的信息层级和日记入口 | 可参考陪伴式表达，但其页面不是关系图实现，且仓库未标明许可证，不复制源码 |

最终路线：首版使用原生 WXML/WXSS 绝对定位，绘制一个中心猫和最多 6 个邻接节点；完整关系以列表作为无障碍、可编辑的后备视图。这样无需第三方依赖，也避免 Canvas 内文字、高清屏适配和点击命中难以维护。若二期节点明显增加，可只将连线层替换为 Canvas 2D，头像、姓名和按钮仍保留为 WXML。

## 3. 关系类型

| 类型 | 含义 | 记录依据示例 |
|---|---|---|
| 贴贴搭子 | 稳定的主动亲近 | 依偎、互相梳毛、主动靠近 |
| 玩耍伙伴 | 双向且能自然停止的游戏 | 轮流追逐、发起游戏、结束后放松 |
| 平静同住 | 能共享生活空间 | 共同休息、路过不紧张、资源使用平稳 |
| 熟悉中 | 正在适应彼此 | 短时接触、仍需隔离门或逐步交换气味 |
| 需要空间 | 存在压力或资源冲突 | 持续追逐、堵路、护食、躲藏、频繁哈气 |
| 亲缘关系 | 主人已经确认的亲子或同窝 | 领养/繁育记录；不由照片或 AI 推断 |

关系网络分为两个互不自动转换的层次：

- 本机私有角色卡以排序后的 `petAId/petBId` 作为“一对猫”的容器，内部 `schemaVersion=2`；同时保存 `directionMode`、`fromPetId`、`toPetId`、`fromRole` 与 `toRole`。朋友、玩伴、室友等可使用 `↔`，亲子和照护身份使用明确的 `→`。排序只用于本地容器去重，不代表箭头方向。
- 云端社区观察边使用有序 `(communityId, fromCatId, toCatId)`；端点绝不排序，v2 的 `directionKey=fromCatId::toCatId`，因此 `A → B` 与 `B → A` 是两条独立边。legacy 边使用 `directionKey=legacy::<edgeId>`，不会占用 v2 方向。云端边只聚合可观察互动，不承载亲缘或永久身份。

完整云端字段、盲投、v1 只读和索引迁移规则见 [`猫际有向关系云端契约-v2.md`](./猫际有向关系云端契约-v2.md)。

## 4. 首版交互

1. 首页和猫咪档案页进入“猫际关系网”。
2. 默认以最近更新的猫咪为中心，点击外围猫咪切换焦点。
3. 已记录关系显示彩色连线；未记录的猫仍显示为“待记录”。
4. 在下方关系卡选择一种关系，并可补充不超过 160 字的观察证据。
5. 保存后给予“关系卡已点亮”的即时反馈，不设置连续打卡、惩罚或过期奖励。
6. 删除本机猫咪档案时同步清理相关私有角色卡；不会擅自删除小屋成员共同引用的云端观察边。

## 5. 隐私、AI 与安全边界

- 私有猫档案和角色卡保存在微信本机存储，不自动上传 CloudBase；邀请小屋中的社区观察投票是另一套独立数据，不会覆盖私有角色卡。
- MiniMax 不参与关系类型的直接判定，也不能仅凭单张图片确定是否是同一只猫或是否存在亲缘关系。
- 如果未来加入 AI 总结，必须同时保存原始观察、时间和用户确认状态，AI 输出只能是“建议复核”。
- “需要空间”不是行为诊断；突然攻击或显著行为改变需要提醒用户排查疼痛、疾病并咨询执业兽医或猫行为专业人士。

## 6. 分阶段演进

### 阶段 A：本地关系卡（本次实现）

- 原生焦点关系图、关系类型、观察备注、删除联动。
- 支持常见多猫家庭；图中最多显示 6 个伙伴，列表始终展示全部。

### 阶段 B：互动事件时间线

- 新增“互相梳毛、玩耍、争抢、回避”等事件，记录时间、地点和资源背景。
- 根据最近 7/30 天记录形成趋势，但不自动覆盖主人确认的关系卡。

### 阶段 C：个体识别辅助

- 先完成同一只猫的 embedding 匹配与用户复核，再把照片事件关联到猫档案。
- 低置信度照片必须进入“待确认”，不可自动写入关系。

### 阶段 D：CloudBase 邀请小屋与社区观察边

- 使用可信 OpenID 派生的不可逆 `ownerKey` 隔离个人投票，客户端不能直读写关系集合。
- 以规范 `catId` 建立 v2 有向观察边，`A → B` 与 `B → A` 独立投票；私有角色卡不自动同步。
- 启用写入前必须完成 `uniq_relationship_direction_key(communityId, directionKey)` 唯一索引迁移、v1 只读兼容、分页或截断标记和真实微信登录态验收。

## 7. 验收指标

- 两只及以上猫时，用户可在 3 次点击内创建关系。
- 所有按钮触控区域至少 `88rpx`，大号系统字体下关系说明和健康警告不截断。
- 删除本机猫档案后不存在孤儿私有角色卡；云端同一有序端点不能产生重复边，但 `A → B` 与 `B → A` 必须允许同时存在。
- 关系图最多展示 7 个节点（1 个焦点与 6 个伙伴），完整关系列表始终可访问。
- 没有任何 UI 文案暗示 AI 能凭照片准确判断血缘、友好程度或医学原因。
