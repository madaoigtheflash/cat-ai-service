## 当前目标

首页呈现所有微信用户**主动公开且审核通过**的猫咪动态，而不是本机档案列表或演示角色的内容。底部保留：首页、档案、中间识猫入口、社交、我的。知识页退出路由和导航，旧源码暂存作历史备份。

核心链路：拍照观察 → 登记本地档案 → 选择分享的故事、照片与基础名片 → 明确确认公开 → 审核 → 首页动态 → 评论 → 回应通知。

原档案、照护、猫际关系、小屋新建/加入/邀请和目击流程保留；原精选花园收纳到「我的 → 喜欢的猫片」。私密小屋目击不迁移到公共广场。

## 照片共享增量（2026-09-29）

历史阶段的「增加照片共享功能」按现有公开动态路径实现，未将私密小屋照片或档案自动公开。**当时客户端和服务端安全增量已实现，但线上照片发布尚未开放；最新状态见文首。**

### 本轮实现

- 首页/社交入口明确为「分享照片 / 故事」；允许选择 1–3 张照片、正文选填，也保留纯文字故事。空文字加空照片拒绝提交。
- 第一张作为封面，可显式重排；换封面、增删照片、改正文会更新请求编号并撤销公开确认。照片仍只在确认提交后上传。
- 准备、整体上传进度、服务端提交分别显示；100% 只表示文件上传，不冒充公开或审核通过。上传进度兼容微信 UploadTask 回调和 Promise 返回，忽略迟到、倒退和无效进度。
- 提交期间禁止更改内容/重复发起；离开页面后忽略旧 UI 回调。旧请求完成不会覆盖或清空在新页面编辑的新草稿；不同意图不能误用前一个在途请求的成功结果。
- 已审核公开的详情新增原生「分享给微信好友」，待审/拒绝内容不提供该按钮；分享处理器也不会把未公开原图带出。
- 遵循 `cat-miniapp-ui` / `impeccable` 的既有樱花粉系统，照片预览 4:3、控件放在图外、保留系统中文字体和安全区；修复微信 style:v2 导致的按钮压窄及禁用文字过浅。

### 安全前置与部署

- 独立复核发现实际资源耗尽路径：原实现先全量下载图片，之后才检查 5MB；失败请求又不会到达保存阶段的配额。已修复为审核/媒体 I/O 前事务性计入尝试额度（每人每天 30 次、至少间隔 2 秒），已提交的准确重试不额外计数；成功发布的 12 次/日、10 秒间隔仍保留。
- 新增 `bounded-media.js`，只接受当前环境内限定路径的文件 ID，经可信 SDK 签发后使用有界 HTTPS 流读取。应用最多消费 5MB + 1 哨兵字节，超限中止；签发 5 秒、读取 10 秒期限；拒绝重定向、压缩、部分响应和错误签发结果。提交、人审源图、审核副本回读及诊断均复用此读取器。
- 安全增量已部署到 `catCommunity`，11 个运行时/配置文件 SHA-256 回读一致，无新增依赖、集合或收费资源。旧档案、小屋、其他云函数未改动。
- 本轮合成图探针在运维身份检查处返回 `FORBIDDEN`，未进入上传/读取、未创建测试云文件；不能把它算作新读取器的真实云端验证。两个开关已重新回读为 false，函数 Active/Available。真实微信只读检查 `mediaContext=MEDIA_DISABLED`、运维入口 `FORBIDDEN`、公共列表正常；当前已有 1 条用户动态，未清理或修改。

## Direction contract

**THESIS**：先让人读到猫的故事、找到可以接的话，再进入工具；不再用档案数据概览占据首页。

**OWN-WORLD**：继承 DESIGN.md 的樱花粉与奶白原生组件，中文系统字体，深玫瑰色主要操作；88rpx 触控、可换行正文和底部安全区。

**STORY**：不养猫也可以分享和评论；识猫登记只是可选的内容来源，不是入场门槛。公开范围在提交前单独确认。

**FIRST VIEWPORT**：紧凑广场标题与识猫/分享入口，随后单列动态：分享者、故事、4:3 猫片、猫咪名片、评论预览与接句话。没有虚构热度或种子帖子。

**FORM**：用户明确指定的原版功能整合，继承已有信息流方向；本次不是重新选择视觉世界，不运行概念抽签。特色交互是识猫登记后的主动分享，以及可编辑开场草稿，绝不自动发送。

**FINISH**：unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## 边界

- 新增 `catCommunity` 服务，与旧 `catOnlineV2` 和 `catSocialStaging` 隔离；不把 A/B 沙盒当真实广场。
- 服务端从微信调用上下文派生身份；不接受客户端指定发布者。
- 公开名片只含名字、品种、毛色；不上传健康记录、备注、识别原文、本机 ID 或精确位置。
- 照片由用户明确选择，点击提交后才上传；保存本地档案不触发发布。
- 图片审核链路、集合权限、微信内容安全权限需部署后验证；审核失败或不可用时不公开。
- 本次不发布审核版本，不迁移旧数据，不自动启用原型私信；公开运营所需类目、举报处置和隐私条款需另行核实。

### 首次部署后的核查（历史证据）

2026-09-29 再次查询同一个微信工具任务，状态仍为 pending，未重发部署请求或绕过原生确认。存储两种回读仍是 PRIVATE / 空规则；官方 `DescribeCDNChainTask` 返回 FINISHED，但该状态不绑定本次写入请求，所以只用于说明没有观察到进行中的任务，不能证明规则曾成功应用。

官方权限接口响应另有 `Data.Success` 布尔值，先前工具丢弃了它。现已要求该字段必须严格为 true，随后还须回读规则完全相符；false、缺失或字符串等响应均直接失败，不输出原始载荷。本轮仅修改本地诊断/测试逻辑，未重放云端权限写入、未更换存储架构、未开放图片。

随后进行了独立、可清理的真实存储探针：通过管理员 CLI 在 `community-approved/_ownership-probe/` 下创建一个 256 位随机命名的纯文本文件（仅合成说明，不是照片/用户数据），并恢复微信运行时相关 API 的实际实现后测试。当前账号 `downloadFile` 返回 HTTP 200，读取字节与确切探针内容一致；覆盖上传被拒绝（-503002）；删除返回文件级失败状态 1，管理员回读仍确认对象存在。随后管理员仅删除该精确随机路径，回读返回 404。没有保留云端探针或改动其他文件。

这个结果只证明**当前账号对这一 CLI 管理员创建的对象可读、无法覆盖或删除**。不能推出所有用户的权限，不能推断开发者身份有特殊读取权，也不能把 CLI 上传等同于审核云函数上传。官方资料没有给出足以解释此次读取行为的所有权语义，因此仍需第二实际账号及真实审核云函数路径验证。

当时提出的候选兼容路径是保持 PRIVATE、不改变旧文件权限，用全新 256 位随机名称及上传回读后事务性引用避免覆盖。随机命名和回读校验现已作为附加防护实现，尚未替代原 gate；不能声称整个目录禁止客户端创建，图片开关仍为 false。
