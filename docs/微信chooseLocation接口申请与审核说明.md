# 微信 `chooseLocation` 接口申请与审核说明

更新日期：2026-08-29  
小程序 AppID：`wx1112379224ace9f9`  
CloudBase 环境：`cloud1-d6gpjpxunc74669d7`

## 1. 审核版只申请一个位置接口

| 接口 | 是否申请 | 小程序内真实功能 | 代码证据 |
| --- | --- | --- | --- |
| `wx.chooseLocation` | 是 | 用户上传猫咪目击时，主动从微信地图选择本次目击地点 | `miniapp/pages/online/index.js` 的 `chooseLocation` |
| `wx.getLocation` | 否 | 不获取用户当前位置 | 无调用 |
| `wx.getFuzzyLocation` | 否 | 不自动获取模糊位置 | 无调用 |
| `wx.choosePoi` | 否 | 不使用附近地点列表 | 无调用 |
| `wx.startLocationUpdate` | 否 | 不做前台连续定位 | 无调用 |
| `wx.startLocationUpdateBackground` | 否 | 不做后台连续定位 | 无调用，也未声明后台定位模式 |
| `wx.onLocationChange` | 否 | 不监听位置变化 | 无调用 |

不要为了“备用”在微信后台勾选未使用的接口，也不要在申请理由中写“实时定位”“附近猫咪”“轨迹”“后台定位”或“定位用于 AI 同猫识别”。当前同猫模型只使用图片；位置只用于管理员人工核验与小屋模糊热区。

## 2. 可直接粘贴的接口申请理由（300 字以内）

> 本小程序用于邀请制猫友小屋的猫咪目击协作。用户进入“首页—云端猫站—上传一次目击”，主动点击“主动选择本次目击地点”时调用 wx.chooseLocation；位置可跳过或在提交前清除。选点与照片、时间关联，辅助管理员人工核验，并生成约 2 公里粗网格。审核后仅同一小屋成员可见模糊热区，不展示精确经纬度或选点名称。页面不会自动、持续或后台定位，拒绝后仍可无位置提交。

后台申请理由、隐私保护指引、审核备注和客服回复必须统一采用这套事实，不要混用旧版“公开地图”“获取当前位置”等说法。

## 3. 审核员可复现的完整路径

1. 从“首页”点击“云端猫站 · 猫友协作”。
2. 创建或加入一个邀请制猫友小屋。
3. 在“上传一次目击”选择猫咪照片。
4. 滚动到“本次目击地点（可跳过）”，点击“主动选择本次目击地点”。
5. 在微信地图选点并返回；页面显示本地选点名称和“清除本次目击地点”。
6. 提交后记录先进入管理员待审核状态。
7. 管理员审核通过后，进入“小屋关系与地图”；地图只显示约 2 公里的模糊热区，并明确提示不获取用户当前位置。

拒绝位置权限、在地图页取消或完全不选择位置，都不能阻止照片上传和其他基础功能。

## 4. 数据处理口径

| 数据 | 保存与可见范围 |
| --- | --- |
| 微信地图返回的 POI 名称/地址 | 仅用于当前页面向用户确认，不上传，不写入成员热区 |
| 用户主动选择的精确经纬度 | 写入云端私有目击记录并用于生成粗网格；不返回普通成员或小屋管理员页面 |
| 用户手填的粗略地点备注 | 私有保存；仅待审核阶段向上传者和有审核权限的管理员返回 |
| 审核后的成员地图 | 只返回约 2 公里网格中心、聚合数量和模糊时间，不返回精确坐标或自由文本地点 |

相关集合必须保持 `ADMINONLY`，小程序只可通过云函数读取字段过滤后的投影。地图组件保持 `show-location="false"`。

## 5. 隐私保护指引建议文本

位置用途可填写：

> 当你在“上传一次目击”中主动点击地图选点时，我们会处理你选择的位置信息，用于把猫咪照片、观察时间与目击地点关联，辅助小屋管理员审核，并生成约 2 公里模糊热区。该功能可跳过，不会自动、持续或后台定位；精确位置不会返回普通成员或小屋管理员页面。

地点备注可填写：

> 你手动填写的粗略地点备注仅用于待审核阶段，由上传者和有审核权限的小屋管理员查看；审核后的成员地图不展示该备注。请勿填写住宅门牌或其他敏感地址。

提交审核前，必须在微信后台填写真实且可执行的：

- 精确位置、地点备注和照片的保留期限；
- 用户申请删除或更正数据的入口/客服渠道及预计处理时限；
- 运营主体名称与联系方式。

当前代码没有“用户可随时自行删除云端目击”的完整入口，因此隐私指引不得作此承诺；可以如实提供人工删除渠道，待删除接口上线后再更新表述。

## 6. 截图与录屏清单

至少准备以下同一版本、同一体验账号下的材料：

1. 首页“云端猫站 · 猫友协作”入口；
2. “上传一次目击”页面中位置可跳过、主动选点、不会持续定位的完整说明；
3. 点击按钮后出现的微信地图选点界面；
4. 返回后显示已选地点和清除按钮；
5. 拒绝/取消后仍能无位置提交；
6. 管理员审核页；
7. 审核后的小屋模糊热区及“不获取当前位置”说明。

录屏不要剪掉主动点击按钮的动作，否则审核员可能误判为页面自动定位。

## 7. 代码与配置核对表

| 核对项 | 当前约束 |
| --- | --- |
| `miniapp/app.json.requiredPrivateInfos` | 必须严格为 `["chooseLocation"]` |
| `miniapp/app.json.permission` | 只保留 `scope.userLocation`，说明主动选点和模糊热区用途 |
| 后台“地理位置接口申请” | 只申请 `chooseLocation` |
| 页面初始化 | 不得调用任何位置接口 |
| 选点失败或拒绝 | 不得阻断无位置上传 |
| 地图组件 | `show-location="false"` |
| 生产代码禁用 | `getLocation`、`getFuzzyLocation`、`choosePoi`、前台/后台连续定位和位置监听 |
| 对外地图数据 | 不含精确经纬度、微信 POI 名称、用户自由文本地点 |

自动化契约位于 `miniapp/tests/location-permission-contract.test.cjs`。每次提审前运行全部 Node 测试，防止后续功能误加位置接口或改回精确地址展示。
