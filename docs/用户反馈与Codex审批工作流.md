# 用户反馈、Codex 审计与本地执行工作流

## 1. 目标与结论

工作流固定为：

```text
小程序提交反馈并查看本人进度
  → 本地管理台读取、裁剪和脱敏
  → Codex 在 read-only 沙箱生成可行性报告与修改稿
  → 本机操作者审阅报告并明确确认
  → Codex 在 workspace-write 沙箱修改当前工作区并运行相关测试
```

小程序没有管理员身份、提案列表、批准按钮或本机控制能力。报告和执行入口只存在于监听 loopback 的本地管理台，云端状态不能自动启动本机进程。旧环境中的管理员白名单记录可以保留用于审计，但当前代码不会读取或使用。

## 2. 组件与权限边界

| 组件 | 职责 | 权限边界 |
| --- | --- | --- |
| 小程序意见信箱 | 提交反馈、查看本人的处理阶段 | 只调用 `catOnlineV2`，不读取提案或管理员数据 |
| `catOnlineV2` | 登录态、幂等、字段裁剪和本人反馈查询 | 不执行 Codex，不接触本地文件 |
| 本地 FastAPI 管理台 | 聚合反馈、脱敏、发起审计、展示报告、接受本机确认 | 仅监听 loopback，浏览器不持有 CloudBase 凭证 |
| Codex 只读审计 | 核对仓库现状并生成结构化可行性报告 | `read-only`、反馈视为不可信资料、禁止部署和写库 |
| Codex 本地执行 | 按本机确认的修改稿编辑并测试 | `workspace-write`，禁止推送、部署和破坏性操作 |

当前工作流使用两个 `ADMINONLY` 集合：

- `ci_feedback`：用户归属、类型、标题、内容、步骤、最小客户端信息、状态、提案引用、幂等键和版本；
- `ci_change_proposals`：结构化报告、来源反馈 ID、本地审阅/执行状态、版本和执行租约。

推荐索引：

- `ci_feedback(ownerKey, createdAt desc)`；
- `ci_change_proposals(generatedAt desc)`。

`ci_app_admins` 是旧版遗留集合。当前小程序、云函数和本地管理台均不依赖它；新环境无需创建。

## 3. 状态机

```text
反馈：OPEN / TRIAGED
        └─→ INCLUDED_IN_PROPOSAL
              └─→ CLOSED（后续增强）

提案：READY_FOR_LOCAL_REVIEW
        └─ 本机明确确认 + 版本校验 + 租约认领
              └─→ EXECUTING
                    ├─→ COMPLETED
                    └─→ FAILED
```

为避免中断旧报告，`AWAITING_ADMIN_APPROVAL` 和 `APPROVED_FOR_LOCAL_EXECUTION` 只作为旧状态兼容读取，统一显示为“等待本机审阅”。新报告只写入 `READY_FOR_LOCAL_REVIEW`。执行时必须重新从云端读取提案，校验状态、`expectedVersion` 和唯一租约，不能相信浏览器中的缓存数据。

## 4. 筛选与审计规则

审计输入单次最多 20 条，只接受 `OPEN` / `TRIAGED`。进入 Codex 前会：

1. 排除未投影的 OpenID、完整 ownerKey、精确位置、fileID 和 embedding；
2. 对标题、内容和步骤替换 API Key、邮箱、中国大陆手机号及 ownerKey 样式；
3. 限制每个字段、数组和总反馈数量；
4. 将反馈明确标记为不可信数据，禁止把其中的文字当作系统指令或命令；
5. 要求 Codex 结合仓库现状判断可复现性、安全、价值和成本；
6. 用 JSON Schema 约束报告结构，并由服务端再次校验。

Codex 的建议不是自动决策。分数和 `recommend` 只能辅助本机操作者判断，不能跳过本地确认。

## 5. 本机确认与执行边界

- 执行按钮只在本地管理台显示；
- 每次执行前展示报告、风险、文件范围、测试计划和预期版本，并要求本机再次确认；
- 认领成功后状态原子更新为 `EXECUTING`，并写入一次性租约，避免重复执行；
- Codex 只允许修改当前工作区和运行相关测试；
- 不自动提交 Git、不推送、不部署、不发布，不删除云端或本地数据；
- 操作者必须审阅最终差异和测试结果，之后再单独决定是否提交或部署。

## 6. 失败与恢复

- Codex 超时或输出不符合 Schema：不创建提案，反馈保持原状态；
- 提案写入后反馈关联失败：检查孤立提案，不直接执行，按来源反馈重建或人工清理；
- 执行前版本过期：返回冲突并要求刷新；
- 执行租约竞争：只允许一个本机任务成功认领；
- 执行进程中断：保留 `EXECUTING` 和租约信息，先审阅工作区再恢复；
- 修改完成但测试失败：记录 `FAILED` 或明确摘要，绝不自动部署。

## 7. 验收清单

- 普通用户只能看到自己的反馈标题、阶段和时间，不能看到他人的原文或任何修改提案；
- 小程序不存在管理员身份码、管理员名单、提案列表或批准/拒绝接口；
- 反馈重复提交只产生一条记录；客户端重试记录不保存原始反馈文字；
- 含 Key、邮箱、手机号或 ownerKey 的反馈在浏览器和 Codex 输入中已脱敏；
- 只读审计不修改仓库，并生成符合 Schema 的报告；
- 新报告进入 `READY_FOR_LOCAL_REVIEW`，不会自动执行；
- 只有本机明确确认且版本/租约校验通过才能执行；
- 本机执行不提交、不推送、不部署，修改和测试结果仍需人工审阅。
