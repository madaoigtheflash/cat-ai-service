# Cat-AI × CATO 多分支实验覆盖表

本轮授权：为每种可审计的结合方向建立独立 GitHub 分支，由独立智能体开发，交用户选择；不自动合并、不发布小程序、不改生产云数据。

“穷尽”在此采用有限覆盖定义：以已有 Cat-AI 场景和 CATO 已公开能力构成交叉矩阵，每格归入一个实验或明确拒绝／延期。任意功能集合的排列与所有未来创意不是一个能被证明穷尽的有限任务；本表不作此承诺。

## 拒绝与延期矩阵

| 组合 | 决定与原因 |
|---|---|
| 识猫／日记／知识 → 诊断、药量、治疗日程 | 拒绝自动判断；只记录用户或兽医已确定事项 |
| 档案、日记、账单、小屋内容 → 自动公开 | 拒绝；仅主动选择的最小片段进入草稿 |
| 模型／语音／OCR → 无确认执行、发私信、代成员认领 | 拒绝；中间必须可编辑且可取消 |
| 关系投票 → 猫咪亲缘或身份事实 | 拒绝自动定论；保留观察、方向、身份未决与撤销 |
| 地点 → 实时追踪与精确公开点位 | 拒绝；实验仅粗略区域，生产须复用权限和模糊化边界 |
| 猫人格 → 冒充真人、虚构回应、惩罚打卡 | 拒绝；示例身份及数据始终标记模拟 |
| 微信主动提醒、后台通知 | 延期接入；本地到期展示不宣称已推送 |
| 真实多端、小屋并发、服务端私信 | 本轮仅状态与权限契约模拟；需独立云沙盒与双账号验收 |
| 账号换绑、支付、自动财务接入 | 延期；没有受验证的身份与安全契约，不创建假绑定成功 |
| 公众号自动回复与菜单 | 延期；未核实账号类型与权限，不凭竞品宣传推断 |

## 实验共同约束

- 以当前小程序源码白名单快照为基线；不复制本机私钥、安装目录、运行数据和私有配置。
- 默认游客 AppID，关闭云初始化；原云服务适配器在实验运行时拒绝调用。
- 新数据只写 `catai_cato_lab_v1:<variant>:`。不覆盖原档案，不自动读取原照片。
- 每个分支从同一个基线出发，只实现自己的实验，不互相 cherry-pick。
- 可选原档案导入必须用户主动触发，只读 ID 和名字；示例数据不伪装为用户真实猫咪。
- 各分支提供 `docs/cato-lab/REVIEW.md`：实现范围、操作步骤、测试命令与真实结果、模拟边界、待完成项。
- 每个分支新增 `miniapp/tests/cato-<variant>.test.cjs`；测试业务状态、无效输入、取消／幂等／存储失败及边界。
- 保留中文系统字体、88rpx 操作区、自然换行、底部安全区、无连续打卡压力。
- 最终审计由用户决定；未验证项必须标明，不能把单元测试称为真机通过。

## 开发与审计入口

在微信开发者工具导入分支工作树的 `miniapp/`，先进入「方案审计入口」，再点「打开本分支实验」。游客工程不接生产云。

```powershell
node --test miniapp/tests/cato-*.test.cjs
```

测试照片仅使用仓库已带来源记录的素材；不从 CATO 复制插画或品牌。CATO 资料依据见同目录上级的调研文档。
