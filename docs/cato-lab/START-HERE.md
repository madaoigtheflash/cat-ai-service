# 开始审计：Cat-AI × CATO 多分支实验

每个方向是独立、可运行的微信原生实验，不是已经合并的产品。先查看本目录 `README.md` 的分支总表和截图，再选择一个方向体验；最终保留、组合或放弃都由你决定。

## 1. 不动现有小程序

- 原目录仍在 `codex/personal-release`；本轮没有在原目录切换分支、覆盖已有修改或提交生产代码。
- 每个方向有自己的 `codex/cato-lab/<方向>` 分支和独立工作树。
- 实验使用 `touristappid`，首屏为「方案审计入口」，云初始化关闭。
- 本地命名空间为 `catai_cato_lab_v1:<方向>:`。两个演示角色、投票和权威端都不是真实账号或云服务。
- 本轮没有创建 PR、自动合并、上传小程序、部署云函数或发送真实消息。

## 2. 打开一个实验

本机工作树路径规律：

```text
C:/Users/13622/.codex/worktrees/cato-<方向>/cat-ai-service/miniapp
```

例如选择社交续聊，在微信开发者工具导入：

```text
C:/Users/13622/.codex/worktrees/cato-social-followup/cat-ai-service/miniapp
```

保持游客 AppID，不要改成生产 AppID，也不要打开云开关。编译后点击「打开本分支实验」。

也可以在 review 工作树的 PowerShell 中运行：

```powershell
./tools/open_cato_lab.ps1 -Variant social-followup
```

该脚本先验证分支、游客 AppID、离线开关和首入口，然后只打开开发者工具；不会切分支、安装依赖、部署或清空数据。可加 `-CheckOnly` 只检查。其他机器需指定 `-WorktreesRoot`、`-WechatCli`。

## 3. 建议体验顺序

先审你最关心的用户问题，而不是一次合并十二个入口。

| 想先回答的问题 | 可比较的方向 | 审计重点 |
|---|---|---|
| 怎样从想到照顾它，走到实际做一点？ | capture → care-planner → focus | 录入成本、用户确认、时间不等于完成 |
| 怎样因为一只猫，和别人持续交流？ | social-followup、house-goals | 有上下文的接话、回应自由、协作权限 |
| 怎样留住私人的生活，不默认公开？ | journal、expenses | 真实价值、回顾入口、公开边界 |
| 怎样让陪伴不催促、不冒充真人？ | companion | 语气、安静时段、减少动态、随时停止 |
| 怎样持续观察，而不是急着下结论？ | encounter-review、relationship-observe | 证据、方向、未决状态和撤销 |
| 怎样让建议与意见带来可控改善？ | knowledge-action | 来源、用户自定行动、审阅与人工决定 |
| 多人多端修改时怎样不悄悄覆盖？ | sync-contract | 版本冲突、重复请求、删除墓碑 |

箭头仅表示未来可组合的体验顺序。本轮各分支之间不自动共享数据，没有实现这些跨分支串联。

## 4. 每个方向给出一项决策

使用 [AUDIT-TEMPLATE.md](AUDIT-TEMPLATE.md) 记录「操作—预期—实际」。每个分支选择：

1. 保留，继续完善；
2. 与某个方向组合（写理由）；
3. 修改后再审；
4. 放弃。

建议先问：“用户为什么现在要用它？不记录、不打卡会不会有压力？它是否让人与猫、人与人的互动变得更自然？”不要只看页面像不像某个产品。

## 5. 如何重置与保护资料

实验入口中的重置仅清理本方向命名空间，并需明确确认。不清理现有档案或其他方向。游客项目可能共用开发者工具本地存储，命名空间隔离用于避免串数据。

社交续聊与同步冲突分支做过真实开发者工具中的控制器冒烟，当前本机可能留下明确的合成演练记录。需要从空状态开始时，返回实验入口重置本方向即可；不要清理原小程序的存储。

日记、账本及实验记录只有本机副本；卸载或清理存储可能丢失。实验阶段不要输入真实敏感资料。

## 6. 验证的层级

- **纯逻辑/页面控制器测试**：状态、幂等、取消、失败保存、权限规则等，不代表真实微信云服务。
- **原生编译和截图**：本轮真实微信开发者工具，390×753、默认字号16、基础库3.17.1。截图是某个状态，不代表所有滚动位置和交互都通过。
- **额外原生控制器冒烟**：social-followup 与 sync-contract 使用 `Page.callMethod` 验证本地流程，不等于物理触控、键盘或多设备测试。
- **仍需你/后续阶段验收**：320/375/430px、大字号、输入键盘、安全区全部状态、真机后台行为、真实双账号与云权限、内容审核及类目适配。

基线全量测试为339项。每个分支又增加独立测试；不同分支重复执行相同基线，不能把各列相加当作独立测试总数。

## 7. 复验与依赖

每个方向可运行：

```powershell
node --test miniapp/tests/cato-*.test.cjs
node --test miniapp/tests/*.test.cjs
```

后一个命令包含已有 SDK 与图像处理测试。本机通过被 Git 忽略的目录联接复用原项目已安装的 `catOnline/node_modules`，没有新装依赖或把依赖提交到 GitHub；其他机器需要按原项目依赖配置安装。不要因为缺少依赖就把 skipped 当成通过。

review 分支另提供 `tools/cato_lab_verify_all.cjs` 汇总分支 SHA、干净工作树、专项/全量测试及原生 WXML 编译。需要设置 `WECHAT_WXML_COMPILER` 为本机 `wcc.exe` 路径；缺编译器不会被标为全验收成功。

## 8. 选型后如何合并

不要直接把十二个分支依次 merge 到生产分支。它们故意各自占用实验入口配置，`app.json` 与 `config/cato-lab.js` 的冲突是独立方案的结果。

用户先确定保留方向，再开单独的整合分支：抽取选中的纯逻辑、页面和测试，统一导航、数据契约和隐私边界，然后验证跨模块链路。离线开关不可随手关闭；真实联机需要单独云沙盒、服务端身份校验、访问权限、审核与双账号测试。

本轮的截图和功能测试不构成你的产品批准、上线许可，也不证明市场需求。你的审计结论优先。
