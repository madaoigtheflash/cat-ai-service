# 05 · 私人养猫账本

分支：`codex/cato-lab/expenses`。这是一个可实际保存的本机小账本，不是银行服务、报销系统或 CATO 的云端集成。本实验对照 [COVERAGE.md](COVERAGE.md) 中的「金额草稿 → 确认 → 修改／删除 → 分类汇总」完成独立闭环。

## 实现范围与设计方向

- 原生微信页面：`miniapp/pages/cato-expenses/index`。实验室入口配置已指向该页；原页面和 CloudBase 服务架构不改动。
- 使用项目 `cat-miniapp-ui` 规范及共享 `styles/cato-lab.wxss`：暖粉底、白色手账卡片、深玫瑰确认按钮。分成「草稿／核对」和「月度汇总／明细」两组，没有模拟 AI、奖惩或打卡压力。
- 复用中文系统字体，交互区至少 88rpx，长中文自然换行、弹性布局，底部保留安全区。金额、猫名、备注、错误都不截断。
- 草稿手填金额、日期、分类；猫名和备注选填。用户点击预览后核对全部字段，再明确确认，才写入本机账本。返回修改和放弃草稿均不写记录。
- 已保存记录可以修改金额、日期、分类、名字与备注；仍经过预览和确认。删除显示日期、分类、金额与不可恢复提示，必须再次确认。当前草稿要被其他记录替换时也会先征求确认。
- 按支出日期切换月份，展示该月总额、五个分类的金额／笔数与按日期倒序的明细。修改跨月后自动显示新月份；删除和修改立即重算汇总。
- 金额以整数「分」存储和累加。每笔范围 0.01–999,999.99 元，最多两位小数；拒绝负数、零、指数、千分位、货币符号、无限值和超限值。不接受 `.50` 或 `1.`，请输入 `0.50` 或 `1.00`。
- 支持 1900-01-01 至 2100-12-31 的有效公历日期，独立检查闰年和月末，避免 Date 自动溢出。最多 1,000 笔；最高可能总额仍在安全整数范围内。
- 每次确认有独立操作标识；成功标识与记录在同一份账本快照保存。连点、重复回调、写入后回报失败再重试均不会重复记账。修改／删除检查版本，过期操作不能覆盖新版本。

## 体验路径

1. 将本分支工作树的 `miniapp/` 导入微信开发者工具，使用仓库游客配置；在「方案审计入口」点击「打开本分支实验」。页面首次为空账本，不自动塞入示例。
2. 填 `0.10` 元、当天日期、「猫粮与零食」，可选填猫名和备注。点「预览这笔支出」，检查所有字段。这时尚未保存；点「返回修改，暂不保存」可验证草稿仍在。
3. 再次预览并「确认记入本机账本」。检查出现成功反馈、明细和该月 0.10 元。快速重复点击不会多记。
4. 增加 `0.20` 元、「猫砂与清洁」。确认该月总额正好 0.30 元，两个分类各为 0.10 和 0.20 元。
5. 在明细点击「修改」，把第一笔改成下个月的「医疗与护理」和 `12.50` 元。预览、确认后应显示新月份 12.50 元；切回原月份只剩 0.20 元。
6. 在明细点「删除」，先取消确认，金额应不变；再次点删除并确认，该条明细消失且分类／月度汇总同步减少。
7. 输入 `0`、`-1`、`1.001` 或 `1000000`，不能进入可确认预览；日期控件限制范围，规则层同时验证不可达的异常日期。
8. 返回实验室、重新打开，已确认记录仍在。未确认草稿仅保留在当前页面，离开／重启不保证保留。实验室重置只删除此实验命名空间，删除或重置无法恢复。

## 隐私、失败与模拟边界

- 仅使用 `createStore('expenses')`，账本键为 `catai_cato_lab_v1:expenses:ledger`。记录只存 ID、整数分金额、日期、分类、手填猫名、备注及版本；另存幂等确认 ID。没有写原档案或云数据库。
- 没有读取原猫咪档案、照片、医疗资料或其他本机账本。猫名由用户手填；本轮不提供档案导入，也不请求相机、相册或位置权限。
- 没有模型调用、OCR、语音、自动解析、银行接入、支付、网络上传、自动公开、分享或消息发送。分类总额是真实本地记录的计算结果，不是模拟 AI 结论。
- 本机存储未加密且无云备份，不承诺金融级保密或跨设备同步。清理应用数据或卸载可能丢失；页面顶部始终提示实验性质和持久化边界。不要存银行卡、账户凭据或诊疗敏感原文。
- 存储／校验失败不清空草稿、不显示成功，不提前改动页面账本。读取格式异常阻止写入并隐藏未验证汇总；可重新加载核对，不静默覆盖旧数据。发生不确定写入结果时原预览仍保留，可重试，凭确认 ID 去重。
- 医疗分类只记支出，页面明确不提供诊断、用药或治疗建议。没有自动执行预算、周期扣款或财务建议。
