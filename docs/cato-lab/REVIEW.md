# 09 · 多端一致性实验（sync-contract）

分支：`codex/cato-lab/sync-contract`。入口：`/pages/cato-sync-contract/index`。

## 实现范围

- 两个相互独立的本地模拟副本 A / B，加一个模拟权威端；均属于明确标注的模拟用户 `demo-user`。
- 最小照护事项：新建、改名、标记完成／撤销完成、确认删除；名称 1–80 个字符。
- 每个命令带持久化生成的唯一 ID、设备 ID、用户 ID、事项 ID、操作及 `expectedVersion`。离线时先做本地预测变更、排队；重连按顺序发送。
- 权威端先校验模拟身份，再查幂等回执和记录版本。成功变更增加记录版本及全局修订；同 ID 同语义重试返回旧回执，不二次应用；同 ID 不同语义被拒绝。
- 过期版本停止队列，显示本地意图、当时权威端快照及冲突类型。明确选择保留权威端，或将该事项的待发意图合成新命令，使用最新权威版本重新提交。独立事项的队列不被默默删除。
- 删除保留版本化墓碑。旧创建命令的回执重试、旧修改、新版本覆盖均不能使该 ID 复活；需要新建另一个 ID。
- 模拟回执丢失、同 ID 重试、下一次本地写入失败、失败重试、放弃未确认意图及另一身份读取拒绝，均有页面控件。
- 页面列出每个客户端的本地事项及版本、对应权威版本、离线／待确认队列、最近一次冲突；模拟端列出所有当前记录／墓碑、修订及回执数。

所有已提交状态通过 `createStore('sync-contract')` 写入 `catai_cato_lab_v1:sync-contract:state`。状态转换使用纯函数先构建候选快照；仅保存成功后替换页面状态。保存失败时，已保存状态、副本、队列与模拟权威端不推进，保留重试入口。未提交表单草稿、保存重试动作和故障开关只在当前页面内存在；退出后不会恢复未保存的操作。

## 操作审计

1. 打开分支工程的 `miniapp/`，从「方案审计入口」进入本实验。页面顶部须看到 **SIMULATED · 本机模拟**。建议从上一页重置本实验开始。
2. A 新建“记录饮水情况”，看到模拟权威 v1；B 点“发送 / 拉取”得到相同事项。A 改名或完成，不会自动改写 B 的副本；B 拉取后才看到更新。
3. 冲突：B 切离线并改名；A 在线改名；B 点“重新连接”。应停在 `CONFLICT`，权威端保持 A 的内容。点“保留权威端”放弃 B 对此事项的队列；或点“按最新版本重新提交本地意图”，确认后权威端采用 B 的最终名称和完成状态。
4. 删除竞态：两端先拉取同一事项；B 离线改名，A 删除并确认；B 重连。应显示 `DELETED`，不提供覆盖墓碑按钮。保留权威端后可新建不同 ID 的事项。
5. 回执重试：任一设备切离线并新建，点“重连并模拟一次回执丢失”。权威修订增加，但同一命令 ID 仍留队列。再点“发送 / 拉取”，应提示去重 1 条，权威修订不重复增加。
6. 保存失败：点底部“模拟下一次本地保存失败”，再新建或重连。错误应明确显示，版本及队列不得推进。顶部会列出先前提交的请求；点“重试先前提交”后仅应用该请求一次，不改用现在的草稿。失败后修改输入、取消编辑或切换编辑对象，重试成功也不得清空之后的草稿／编辑状态；成功提示须说明保存的是先前提交，新草稿需另行保存。退出再进入应读取最近一次成功保存的快照。
7. 取消：修改名称后点取消，或删除确认框点取消，不能改变记录；“放弃此设备未确认意图”也必须先确认。回执丢失后放弃队列不等于撤销权威端已应用的命令。
8. 点“用另一模拟身份尝试读取”，应明确拒绝 `demo-other-user` 且返回 0 条记录。
9. 从上一页重置实验只能删除本变体数据；原猫咪档案、其他实验命名空间不应改变。

## 设计与模拟边界

遵循 `DESIGN.md` 与 `cat-miniapp-ui`：复用粉色实验样式、中文系统字体、自然换行、88rpx 触控区及底部安全区；不加入装饰性眉题。事项用于记录已确定安排，不提供医疗判断或用药建议。

本实现是单进程、单个本地快照的可审计状态机，不是生产后端。没有网络请求、CloudBase 调用、真正设备会话、真实登录／授权、多端推送或服务器时钟。另一身份拒绝只证明此纯函数模拟契约，不能作为生产安全认证。模拟端保存与客户端保存在一个本机同步存储调用中，不证明真实分布式原子性或操作系统极端断电行为。

删除是逻辑删除，不是隐私擦除：墓碑的当前记录清空名称，但幂等回执与历史冲突快照仍可能保留旧名称。需从审计入口重置才清除此变体记录。实验无自动回执／墓碑回收；每设备队列限 100 条，新建时本地快照含事项与墓碑达到 40 条会提示重置。此上限不是生产容量或并发保证。

## 重试草稿保护修复（2026-09-29）

独立审计发现：保存失败后的重试会复用先前成功回调，原先无条件清空输入或关闭编辑器，会丢弃用户后来输入的新草稿。现按每设备输入修订、编辑会话修订和提交时表单快照判断：只有未变化的原表单能被清理；取消、换目标、重新打开同一目标，以及改回相同文字，都视为后续操作并保留。失败请求保留原操作及原文字，不能静默改成当前草稿；页面展示待重试请求及成功后的保留说明。切换编辑对象后，重试入口仍可见。

新增 6 个回归用例：新建后续输入保留、同一编辑器新文字保留、取消后换编辑目标、重新打开同一目标同文字、新建文字改动后改回、未变化表单仍可正常清理。上述专项、cato 合集和全量计数均包含这 6 项。此次仅改页面 JS/WXML、专项测试与本文档；保留主代理 `f492646` 的既有变更。本次新增提示的最终 IDE 复验／截图由主代理执行，此处不把编译通过称为视觉通过。
