# 01 · 照护收件箱（capture）审计

## 方向与可体验范围

分支：`codex/cato-lab/capture`。入口：`/pages/cato-capture/index`。

本实验结合 Cat-AI 的日常照护场景与 CATO 的低摩擦录入思路，提供真实可用的本机闭环：多条文字 → 单独可编辑的草稿 → 人工核对时间 → 明确确认 → 私人本机收件箱。既有粉色视觉、中文系统字体、公共实验样式与卡片保持不变，不引入 CATO 品牌或远程素材。

已实现：

- 手动文字录入；两种明确标记为**合成语音文字／合成图片文字**的预写示例。未录音、选图、上传或执行识别。编辑样本文字仍保留合成来源标签；切回手写需要确认清空当前样本。
- 按换行、中文／英文分号、中文句号拆分。每批 1–20 条，输入最多 3000 字，每条 180 字；超过限制报错，不截断或静默丢弃。
- 每条草稿保留原文与来源，支持编辑事项、移除单条、选择日期和时间或明确“先不设时间”。所有时间都初始标记待核对，包括看似明确的日期；规则提示从不直接建立时间戳、重复计划或通知。
- 明确确认整批后实际保存。收件箱支持完成、撤销完成、带确认的删除与重新打开恢复，最多 500 条。
- 取消、仅整理、修改草稿、移除最后一条均不写业务记录。原输入在当前页面中保留；离开页面未确认草稿会丢失，页面已明示。
- 确认时重新读取最新收件箱，在同一存储值内保存事项与批次回执。连续点击和同批重试不会重复创建；删除事项后仍保留回执，旧批次重试不会复活记录。重新录入相同文字并明确确认属于新批次，允许成为新事项。
- 写入异常保留草稿。若写入结果不明，暂时锁定草稿编辑，重试先核对回执；取消只丢弃草稿并重读收件箱，不声称撤回可能已经成功保存的事项。读失败或损坏数据不会静默以空收件箱覆盖。

## 数据与安全边界

- 仅通过 `services/cato-lab.createStore('capture')` 读写 `catai_cato_lab_v1:capture:inbox`。没有新增依赖，没有修改原版存储，也没有读取原档案／照片；本方向未实现可选档案导入。
- 存储包含版本、事项、批次回执。事项包含内容、原文、来源、人工时间选择、创建时间与完成状态；无身份绑定、云同步、共享成员或公开发布。
- 公共实验入口可清理本实验命名空间。批次回执不会因删除单条而删除，只在重置实验时清理。回执长期累积可能消耗本机存储；写满时显示错误并保留草稿。
- 云初始化与生产云传输继续禁用。没有请求网络、真实 ASR/OCR/LLM、订阅消息、后台提醒、实际发布或部署。
- 不推导诊断、药物、剂量或治疗安排。输入若包含此类文字仅作为用户原文记录，不代表医疗建议；页面持续显示就医安全提示。
- 日期时间是用户手动选择的本地钟表文字（2000–2100 年），不转换时区、不保证到期执行。无到期通知；“今晚”“周末”“每周”等词不会被当成已确定的时间或重复规则。
- 本机私人实验存储不等于加密保险箱。清缓存／卸载可能丢失；没有跨设备、多人并发或账号隔离保证。

## 手工体验／验收步骤

1. 微信开发者工具导入本分支 `miniapp/`，保留游客 AppID 和实验配置；从“方案审计入口”打开本分支实验。确认“离线实验 · 只存本机”及医疗安全说明始终可见。
2. 输入 `明天换水；周末洗食盆；整理玩具`，点“整理为可编辑草稿”。应有三条，原文仍在，时间均待核对；立即确认应被阻止，收件箱仍为空。
3. 编辑第一条内容并选定日期和时间；第二／三条选择“先不设时间”。取消任一日期选择器不应悄悄补齐时间；缺日期或时间时不能确认。
4. 先取消整批并确认收件箱未变化，重新整理后逐条核对，明确确认。应保存三条、清空当前草稿；再次点击不增加记录。离开后重进应看到同样三条。
5. 标记一条完成再撤销；删除另一条时先取消弹窗，再确认删除；只有后者删除本实验事项。
6. 分别载入合成语音和合成图片文字，修改内容后确认，收件箱仍显示合成来源。没有实际录音／图片授权或网络上传。尝试载入样本覆盖已有输入时取消弹窗，应保留原输入。
7. 使用开发者工具的 Storage 面板检查：业务值只出现在 `catai_cato_lab_v1:capture:inbox`，不改变 `catai_mini_pets_v1` 等原版键；重置实验仅清理 capture 空间。
8. 存储失败／损坏／结果不确定的注入由自动测试覆盖，避免在真实档案设备上破坏存储。可独立运行测试复核失败时草稿及回执行为。
9. 默认与大号系统字体、窄屏和底部安全区分别检查：长中文事项、错误提示、按钮、日期／时间选择器、20 条草稿均自然换行；操作区至少 88rpx，键盘不永久遮挡确认／取消操作。
