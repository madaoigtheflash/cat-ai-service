## 独立审计发现的 P2：重试旧保存清空新草稿（已修复并复验）

范围：`sync-contract` 页面控制器。发现时提交为 `f492646f7663a0d4f5a0896e11fc6c21a25afa12`。

最小复现：

1. 设备 A 输入 `first attempt`，开启“下一次保存失败”，点击新建。
2. 将输入改为 `newer user input must survive`。
3. 点击重试。

旧结果：旧请求保存成功，但旧 `afterSave` 回调无条件清空后来的输入。编辑已有事项也会关闭包含新文字的编辑框。这是可以用页面自带故障开关触发的真实本地数据体验缺陷，不是把模拟环境当云端问题。

修复提交：`d22ff38621dbb353d201e83db005a3c1d3f0760f`。

- 给每个新建输入与编辑会话维护修订号，清理只作用于当初提交的那一版表单。
- 重试始终保留旧请求语义，不静默换成新输入。
- 新输入、取消后换对象、重开相同对象或把文字改回原样，都不会被旧回调清除。
- 待重试区域显示先前请求摘要；成功后明确说明新草稿仍需另行保存。
- 增加6项持久化回归；不降低或绕过原有断言。

主代理在真实开发者工具中，使用 `tools/cato_lab_retry_smoke.cjs` 复验新建与编辑两条失败→改输入→重试流程，结果通过。该脚本通过 `Page.callMethod` 操作真实页面控制器，不等于物理触控或真机键盘测试。
