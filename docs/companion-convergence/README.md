独立开发分支：`codex/cat-companion-convergence-20260930`。不覆盖原工作目录，不部署线上。

建议先读 [三轮体验报告](EXPERIENCE-REPORT.md)，再看 [验证记录](VALIDATION.md)、[界面设计检查](DESIGN-CHECK.md) 与 [产品/交互边界](BRIEF.md)。

## 这版怎么体验

微信开发者工具导入本分支的 `miniapp/`，AppID 沿用原项目。Windows 可运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/open_companion.ps1
```

这是开发分支，不是游客沙盒。真实云服务只在使用既有功能时按原机制调用；请不要把测试照片或示例记录主动发布到生产社区。新虚拟猫文字云函数尚未部署，默认关闭。不要在客户端填写任何模型密钥。

1. 在“聊聊”输入“登记猫咪叫奶糖”，发送后检查确认卡，修改或取消都不会自动公开。
2. 再登记团子，输入“奶糖是团子的妈妈”，检查从/到与双方身份；只有确认才保存。
3. 点击“记地点”，主动选点并填写粗区域，确认后打开本机地图。
4. 点击“历史”，区分旧对话、已确认回执和当前档案；也可从“我的”查看自己的数据。
5. 拍照先本机预览，点“上传并观察”才调用原识猫服务；云返回之后仍需核对，不能自动确定同猫。
6. 点击“社区 → 逛猫友广场”，或保存后点“挑选内容，再分享”；在原编辑器选择照片、核对公开范围，未确认发布前不上传聊天全文。

## 云端文字对话

代码准备见 [catCompanion 说明](../../miniapp/cloudfunctions/catCompanion/README.md)。必须先解决额度/并发限制、隐私及主体审核，再单独部署和实测。源码中的默认模型来自既有代码，未验证账户可用性；本轮无密钥读取和模型调用。

主线的本地引导可以运行，但只是固定规则，不应当被当作完整自由对话产品验收。

## 回退与数据边界

旧社交首页保留为 `pages/home-classic/index`，现作为猫友广场；旧 Git 分支均保留。不要直接删除或回滚自己的微信存储来测试。

新增四个本机键前缀为 `catai_companion_`。猫咪与关系确认仍写原 `catai_mini_pets_v1` 和 `catai_mini_relationships_v1`，所以不是互不关联的第二套档案。位置为独立粗化记录，不会自动写云端小屋。

本机测试脚本会临时备份并恢复明确列出的六个键，不能替代真实备份。若测试进程被外部强制结束，请停止继续清理并从模拟器运行内存中的备份核对；不要调用清空全部存储。

## 审阅重点

- 默认本地引导是否足够明确？你是否期望打开就能自由聊？
- 看见确认卡时，是否清楚哪只猫、关系方向、保存位置和公开范围？
- 哪些说明影响轻松感，哪些不能隐藏？
- 私人历史、照片和地点中，哪些愿意用于云端对话，哪些必须留本机？

这些答案决定下一轮删减与接云顺序，不以“把所有CATO功能搬过来”为目标。
